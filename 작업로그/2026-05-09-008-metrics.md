# Phase 1 / Step 8 — Metrics 계산 모듈

## Plan

설계서 04번 13절의 MVP 지표를 계산하는 `app/backtest/metrics.py` 작성. trade_group 단위로 집계 (부분매도가 여러 번 발생해도 한 trade_group은 한 거래로 카운트).

### 추가할 지표 (MVP)

- [ ] total_return_pct — 이미 BacktestResult에 있음
- [ ] annual_return_pct — CAGR. (1 + total_return)^(365/days) - 1
- [ ] mdd_pct — daily_equity의 최대 drawdown
- [ ] trade_count — trade_group 단위 (완전 청산된 것만)
- [ ] win_rate — 수익 trade_group / 총 청산 trade_group
- [ ] avg_holding_days — entry_date ~ 마지막 청산일 평균
- [ ] avg_profit_pct — 수익 trade의 평균 수익률
- [ ] avg_loss_pct — 손실 trade의 평균 손실률 (양수로)
- [ ] profit_factor — 총 실현 수익 / 총 실현 손실 절대값
- [ ] open_position_count — 미청산 trade_group 수

### 작성할 파일

- [x] `app/backtest/metrics.py` (~150줄)
- [x] `app/backtest/__init__.py`에 calculate_metrics 노출
- [x] `tests/backtest/test_metrics.py` (13건)
  - 빈 result → 0 또는 0.0
  - 단일 수익 trade → metrics 정합
  - 단일 손실 trade → 정합
  - 수익+손실 mix → win_rate, profit_factor
  - 부분매도 시 trade_group이 여전히 1개로 카운트
  - 미청산 trade_group은 trade_count에 포함 안 됨
  - MDD 계산 (daily_equity 사용)
  - 연평균 수익률 (1년 기간 vs 2년 기간)

### 정책

- 모든 % 값은 백분율 (예: 84.2 = 84.2%, not 0.842)
- profit_factor: 손실이 0이면 inf 또는 None (테스트로 결정)
- 거래 0건이면 win_rate=0.0, avg_*=0.0
- 보유일 0인 당일 청산은 1일로 처리 (KRX 일 단위)

설계 결정:
- **trade_group 단위 집계**: 부분 매도가 N번 일어나도 한 trade_group은 한 거래로 카운트.
  - 매수 1건의 entry_qty와 SELL/PARTIAL_SELL의 quantity 합이 같으면 청산 완료.
  - 그렇지 않으면 open_position_count로 분류.
- **profit_factor 의미 분기**:
  - 손실>0, 수익>=0 → 정상 비율 (수익만 있으면 결과는 0이 아닌 양수가 아니라 0/loss 형태가 안 됨)
  - 손실=0, 수익>0 → math.inf
  - 둘 다 0 (거래는 있지만 손익 0) → None
  - 손실만 있으면 0/loss = 0.0 (수익이 없음을 의미)
- **CAGR 공식**: `(final/initial)^(365/days) - 1`. 초기 자본이 0이면 0, 자본 0 이하면 -100%.
- **avg_holding_days 최소 1일**: 같은 날 매수/매도여도 1일로 계산 (KRX 일 단위).
- **avg_loss_pct는 양수**: 사용자가 보기 편하게 절대값 (예: 5.0% = -5%의 손실).
