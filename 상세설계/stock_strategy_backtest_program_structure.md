# 레고형 주식 매매 전략 생성 및 백테스트 프로그램 구조 정리

## 1. 프로그램의 핵심 컨셉

이 프로그램은 단순 차트 프로그램이나 단순 백테스트 툴이 아니라, **코딩 없이 GUI에서 매매 전략을 레고 블록처럼 조립하고, 저장한 전략을 백테스트하며, 결과를 차트와 리포트로 분석하고, CSV로 내보낼 수 있는 주식 전략 연구 프로그램**입니다.

전체 흐름은 다음과 같습니다.

```text
전략 생성 GUI
    ↓
전략 JSON 저장
    ↓
Python 전략 실행 엔진
    ↓
백테스트 엔진
    ↓
결과 DB 저장
    ↓
차트 / 리포트 / CSV 출력
```

중요한 설계 원칙은 다음과 같습니다.

```text
전략은 Python 코드로 만들지 않는다.
전략은 JSON 데이터로 저장한다.
Python 엔진이 JSON을 읽고 그대로 실행한다.
```

## 2. 전체 시스템 구조

전체 프로그램은 크게 7개 영역으로 나눌 수 있습니다.

```text
1. 전략 생성 GUI
2. 전략 JSON 저장 구조
3. Python 전략 실행 엔진
4. 백테스트 엔진
5. 포트폴리오 / 예수금 관리 엔진
6. 결과 분석 / 차트 시스템
7. DB / CSV 저장 시스템
```

구조도는 다음과 같습니다.

```text
┌────────────────────────────┐
│        전략 생성 GUI         │
│ 레고 블록형 조건 조립          │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│        Strategy JSON        │
│ 매수/매도/필터/자금관리 조건    │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│   Python Strategy Engine    │
│ JSON 조건 해석 / 신호 생성      │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│      Backtest Engine        │
│ 체결 / 보유 / 매도 / 손익 계산 │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│ Portfolio & Cash Engine     │
│ 예수금 / 보유종목 / 일부매도   │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│      Result & Chart UI      │
│ 차트 / 리포트 / 거래내역       │
└─────────────┬──────────────┘
              ↓
┌────────────────────────────┐
│          DB / CSV           │
│ 전략, 결과 저장 / CSV Export │
└────────────────────────────┘
```

## 3. 전략 생성 방식

전략은 사용자가 GUI에서 레고 블록처럼 조립합니다.

전략은 크게 다음 영역으로 구성됩니다.

```text
1. 매수 조건
2. 매도 조건
3. 필터 조건
4. 자금 관리 조건
5. 백테스트 실행 조건
```

예를 들면 사용자가 GUI에서 다음과 같은 전략을 만들 수 있습니다.

```text
매수 조건:
- 종가가 20일 이동평균선 위
- 거래량이 20일 평균의 2배 이상
- RSI(14)가 70 이하

매도 조건:
- 수익률 +7% 이상이면 익절
- 손실률 -3% 이하이면 손절
- 최대 보유일 10일

필터 조건:
- 20일 평균 거래대금 50억 이상
- 코스닥 지수가 20일선 위일 때만 매수

자금 관리:
- 매일 100만 원 매수
- 예수금이 부족하면 수익률 낮은 보유 종목 25% 일부 매도
```

## 4. 전략 GUI 구조

전략 생성 화면은 **레고 블록형 카드 빌더**가 가장 적합합니다.

추천 화면 구조는 다음과 같습니다.

```text
┌──────────────────────────────────────────────┐
│ 전략명 / 저장 / 복사 / 백테스트 실행 / JSON 보기 │
├───────────────┬────────────────┬─────────────┤
│ 블록 팔레트    │ 전략 조립 영역    │ 설정/설명 패널 │
│               │                │             │
│ 가격          │ 매수 조건        │ 선택 블록 설정 │
│ 이동평균       │ 매도 조건        │ 전략 설명      │
│ 거래량         │ 필터 조건        │ 오류/경고      │
│ 보조지표       │ 자금 관리        │             │
│ 캔들          │ 백테스트 설정    │             │
└───────────────┴────────────────┴─────────────┘
```

GUI에서 중요한 원칙은 다음입니다.

```text
조건은 코드처럼 보이면 안 된다.
사람이 읽는 문장처럼 보여야 한다.
```

나쁜 예:

```text

volume_ratio
rsi_level
```

좋은 예:

```text
종가가 20일 이동평균선보다 높을 때
거래량이 20일 평균 거래량의 2배 이상일 때
RSI(14)가 70 이하일 때
```

## 6. 전략 JSON 구조

GUI에서 만든 전략은 내부적으로 JSON으로 저장합니다.

예시 구조는 다음과 같습니다.

```json
{
  "name": "거래량 돌파 스윙 전략",
  "version": "1.0",

  "entry": {
    "logic": "AND",
    "conditions": [
      {
        "type": "price_vs_ma",
        "price_field": "close",
        "ma_period": 20,
        "operator": ">"
      },
      {
        "type": "volume_ratio",
        "period": 20,
        "operator": ">=",
        "value": 2.0
      },
      {
        "type": "rsi_level",
        "period": 14,
        "operator": "<=",
        "value": 70
      }
    ]
  },

  "exit": {
    "logic": "OR",
    "conditions": [
      {
        "type": "take_profit",
        "percent": 7
      },
      {
        "type": "stop_loss",
        "percent": 3
      },
      {
        "type": "max_holding_days",
        "days": 10
      }
    ]
  },

  "filters": {
    "conditions": [
      {
        "type": "avg_trading_value",
        "period": 20,
        "operator": ">=",
        "value": 5000000000
      }
    ]
  },

  "cash_management": {
    "daily_buy_budget": 1000000,
    "cash_shortage_rule": {
      "trigger": {
        "type": "cash_below_daily_buy_budget"
      },
      "action": {
        "type": "partial_sell",
        "sell_fraction": 0.25
      },
      "target_selection": {
        "method": "lowest_return"
      },
      "repeat_until_cash_sufficient": true
    }
  }
}
```

핵심 원칙은 다음입니다.

```text
JSON 안에는 Python 코드를 넣지 않는다.
JSON은 type + parameter 형태의 설정 데이터만 가진다.
실행 가능한 조건은 엔진에 등록된 조건만 허용한다.
```

## 7. Python 전략 실행 엔진

전략은 Python 코드로 변환하지 않고, Python 엔진이 JSON을 읽고 실행합니다.

엔진 구성은 다음과 같습니다.

```text
StrategyEngine
- JSON 전략 로드
- 매수 조건 해석
- 매도 조건 해석
- 필터 조건 해석
- entry_signal 생성
- exit_signal 또는 포지션 기반 매도 조건 전달

ConditionRegistry
- ma_cross
- volume_ratio
- rsi_level
- macd_cross
- price_vs_ma
- new_high_breakout
등 조건 함수 등록
```

조건이 많아질수록 `if / elif` 방식보다 **Registry 패턴**이 좋습니다.

```text
조건 추가 = 조건 함수 하나 작성 + registry 등록
```

이렇게 하면 나중에 GUI도 등록된 조건 목록을 읽어서 자동으로 블록 목록을 만들 수 있습니다.

## 8. 백테스트 엔진 구조

백테스트 엔진은 전략 엔진과 분리합니다.

```text
StrategyEngine:
- 어떤 날 매수 신호가 발생했는가?
- 어떤 날 매도 조건이 발생했는가?

BacktestEngine:
- 실제로 매수했는가?
- 얼마에 체결했는가?
- 수량은 몇 주인가?
- 보유 중인가?
- 언제 팔았는가?
- 수익률은 얼마인가?
```

백테스트 엔진의 하루 처리 흐름은 다음과 같습니다.

```text
1. 날짜별 시세 데이터 로드
2. 전략 조건 평가
3. 매도 조건 먼저 확인
4. 기존 보유 종목 매도 처리
5. 신규 매수 후보 탐색
6. 예수금 확인
7. 예수금 부족 시 현금 확보 규칙 실행
8. 신규 매수 실행
9. 일별 자산 / 예수금 / 보유 종목 기록
```

## 9. 예수금 / 자금 관리 기능

이 프로그램의 중요한 차별화 기능입니다.

예를 들어 다음과 같은 규칙을 넣을 수 있습니다.

```text
매일 100만 원씩 매수
예수금이 100만 원보다 적으면
보유 종목 중 일부를 25% 매도해서 현금 확보
```

이 기능은 일반적인 기술적 조건이 아니라 **포트폴리오 운용 규칙**으로 분리해야 합니다.

자금 관리 블록 예시는 다음과 같습니다.

```text
초기 자금
1일 매수 예산
1회 매수 금액
최대 보유 종목 수
예수금 최소 유지 금액
예수금 부족 시 신규 매수 중단
예수금 부족 시 보유 종목 일부 매도
예수금 부족 시 수익률 낮은 종목부터 매도
예수금 부족 시 수익률 높은 종목부터 매도
예수금 부족 시 보유 금액 큰 종목부터 매도
```

예수금 부족 시 매도 대상 선택 기준은 다음과 같이 설계했습니다.

```text
1. 수익률이 가장 낮은 종목부터 매도
2. 수익률이 가장 높은 종목부터 매도
3. 보유 금액이 가장 큰 종목부터 매도
4. 오래 보유한 종목부터 매도
5. 최근 매수한 종목부터 매도
6. 전체 보유 종목 균등 일부 매도
```

MVP에서는 아래 3개면 충분합니다.

```text
수익률 낮은 종목부터
수익률 높은 종목부터
보유 금액 큰 종목부터
```

## 10. 백테스트 대상 종목군

기본 대상은 한국 시장입니다.

```text
코스피 전체
코스닥 전체
코스피 + 코스닥 전체
관심종목
직접 선택 종목
업종별 선택
시가총액 상위 N종목
거래대금 상위 N종목
```

초기 MVP에서는 다음 정도가 적당합니다.

```text
1. 코스피 전체
2. 코스닥 전체
3. 코스피 + 코스닥 전체
4. 관심종목
5. 직접 선택
6. 시가총액 상위 N종목
```

중요한 점은 **생존 편향**입니다.

현재 상장 종목만으로 과거 백테스트를 하면 상장폐지 종목이 빠져서 결과가 좋아 보일 수 있습니다.

따라서 단계적으로 가는 것이 좋습니다.

```text
MVP:
현재 상장 종목 기준
ETF / ETN / 스팩 / 우선주 / 관리종목 제외 옵션
거래대금 필터 적용

고급 버전:
날짜별 상장 종목 유니버스
상장폐지 종목 포함
거래정지 / 관리종목 이력 반영
생존 편향 방지
```

## 11. 시가총액 상위 N종목 백테스트

시가총액 상위 10종목 같은 방식도 지원할 수 있습니다.

다만 방식이 여러 가지입니다.

```text
1. 현재 기준 시가총액 상위 N종목
2. 백테스트 시작일 기준 시가총액 상위 N종목
3. 매월 시가총액 상위 N종목 재선정
4. 매분기 시가총액 상위 N종목 재선정
5. 매년 시가총액 상위 N종목 재선정
```

MVP에서는 다음 2개가 적당합니다.

```text
현재 기준 상위 N종목
백테스트 시작일 기준 상위 N종목
```

고급 버전에서는 다음을 추가합니다.

```text
월별 / 분기별 / 연별 재선정
유니버스 변경 이력 저장
```

백테스트 실행 설정 JSON 예시는 다음과 같습니다.

```json
{
  "universe": {
    "market": "KOSPI",
    "selection_method": "market_cap_top_n",
    "top_n": 10,
    "selection_timing": "backtest_start_date",
    "rebalance_frequency": "none"
  }
}
```

## 12. 백테스트 전략 선택 방식

전략을 만들고 저장한 뒤, 백테스트할 때는 **전략 라이브러리에서 저장된 전략을 선택**합니다.

흐름은 다음과 같습니다.

```text
전략 생성
→ 전략 저장
→ 전략 목록에 등록
→ 백테스트 실행 화면에서 전략 선택
→ 종목군 / 기간 / 자금 / 체결 조건 선택
→ 백테스트 실행
→ 결과 저장
```

백테스트 화면 구조는 다음과 같습니다.

```text
1. 전략 선택
2. 전략 미리보기
3. 백테스트 대상 선택
4. 기간 선택
5. 초기 자금 설정
6. 수수료 / 세금 / 슬리피지 설정
7. 실행 전 점검
8. 백테스트 실행
```

중요한 설계 원칙은 다음입니다.

```text
전략 = 어떤 조건으로 사고팔 것인가
백테스트 실행 설정 = 어떤 기간, 어떤 종목, 어떤 자금 조건으로 테스트할 것인가
```

그리고 백테스트 결과에는 반드시 **실행 당시의 전략 JSON 스냅샷**을 저장해야 합니다.

그래야 나중에 전략을 수정해도 과거 백테스트 결과가 유지됩니다.

## 13. 백테스트 결과 화면

백테스트 결과는 숫자 표만 보여주면 안 되고, 차트 중심으로 보여줘야 합니다.

전체 결과 화면은 다음 구조가 좋습니다.

```text
상단:
- 전략명
- 기간
- 대상 종목군
- 초기 자금
- 실행일

요약 카드:
- 총 수익률
- 최종 자산
- MDD
- 승률
- 거래 횟수
- 평균 보유일

탭:
[요약]
[포트폴리오 전체]
[종목별 상세]
[거래내역]
[월별성과]
[리스크]
[자금관리]
[CSV 다운로드]
```

## 14. 종목별 상세 차트

선택한 종목을 고르면 다음과 같은 차트를 보여줍니다.

```text
상단:
종목 봉차트
- 캔들
- 이동평균선
- 매수 / 매도 마커

중단:
거래량 차트

하단:
수익률 그래프
- 전략 누적 수익률
- 해당 종목 단순 보유 수익률
- 벤치마크 수익률
```

중요한 UX 결정은 다음입니다.

```text
봉차트 위에 수익률 숫자를 계속 표시하지 않는다.
차트가 지저분해지기 때문이다.

기본은 매수 / 매도 마커만 표시한다.
수익률은 6개월 또는 1년 단위로만 표시한다.
상세 수익률은 마우스 오버 툴팁으로 보여준다.
```

예시 툴팁은 다음과 같습니다.

```text
2024-06-14

종가: 72,500원
전략 누적 수익률: +18.4%
종목 단순 보유 수익률: +11.2%
벤치마크 수익률: +6.7%
보유 상태: 보유 중
평가 수익률: +4.3%
예수금: 1,240,000원
총자산: 11,850,000원
```

매도 마커에 마우스를 올리면 다음과 같이 보여줍니다.

```text
매도 체결

날짜: 2024-04-05
매도가: 78,200원
수량: 13주
수익률: +8.6%
손익: +80,600원
보유일: 17일
매도 사유: 익절
```

```text

   - 매수 / 매도 거래 내역
```

```text
- 매수 / 매도 거래 내역

- 일별 자산, 예수금, 수익률, MDD

cash_events
- 예수금 부족, 일부 매도 이벤트

symbols
- 종목코드, 종목명, 시장, 업종

- 일봉 시세 데이터
```

## 22. 최종 정리

이 프로그램은 다음과 같이 정의할 수 있습니다.

```text
GUI에서 주식 매매 전략을 레고 블록처럼 만들고,
전략을 JSON으로 저장하며,
Python 엔진이 JSON을 해석해 백테스트하고,
결과를 차트, 리포트, CSV로 분석하는
한국 주식 전용 전략 연구 플랫폼
```

핵심 차별점은 다음입니다.

```text
1. 코딩 없이 전략 생성
2. 전략을 JSON으로 저장
3. Python 코드 변환 없이 JSON 실행 엔진 사용
4. 레고 블록형 GUI
5. 한국 코스피 / 코스닥 전체 백테스트
6. 시가총액 상위 N종목 테스트 지원
7. 예수금 부족 시 일부 매도 같은 현실적 자금 관리
8. 봉차트 위 매수 / 매도 마커 표시
9. 수익률은 깔끔하게 간격 표시 + 마우스 툴팁
10. 백테스트 결과 DB 저장 + CSV Export
```

가장 중요한 설계 철학은 다음입니다.

```text
전략은 데이터로 만든다.
실행은 엔진이 담당한다.
GUI는 사람이 이해하기 쉽게 만든다.
백테스트 결과는 숫자가 아니라 차트와 해석으로 보여준다.
```

이 방향으로 가면 단순 백테스트 프로그램이 아니라, **전략 생성·검증·개선이 가능한 주식 전략 연구소**가 됩니다.
