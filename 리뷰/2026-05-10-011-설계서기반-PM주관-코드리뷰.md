## 2. 🔴 Critical (반드시 수정 — 정확성 정책·결정론·보안·재현성 위반)

### C1. exit_position 라우팅이 ConditionRegistry를 우회

- **위치**: `backend/app/backtest/engine.py:64,143-209`
- **위반 절**: 02번 5절, 03번 4~5절, CLAUDE.md 핵심원칙 #2
- **문제**: `_evaluate_exit_position`이 ConditionRegistry를 거치지 않고 `r["type"] == "stop_loss"/"take_profit"/"max_holding_days"`로 if/elif 하드코딩한다. 결과적으로 `take_profit`은 메타로만 등록될 뿐 엔진은 함수를 호출하지 않으며, `stop_loss`/`max_holding_days`는 Registry에 등록 자체가 없는데 엔진이 직접 해석. **`requires_position` 분기 자체가 무력화**되어 있다.
- **정책 인용**: 03번 4절 — "조건 type → 함수 매핑은 ConditionRegistry가 단일 출처".
- **권고**: 엔진은 rule 순회 시 `condition_registry.evaluate_position(type, position, row, condition)`을 호출하고, 갭 다운/일중 손절 우선 같은 13.3 정책 분기는 각 포지션 조건 함수 또는 PriorityResolver에 캡슐화한다.

### C2. CashManager 강제 매도가 ExecutionModel을 우회

- **위치**: `backend/app/portfolio/cash_manager.py:60-67`
- **위반 절**: 13.5(호가 단위), 13.6(거래세 시계열), 13.7(수정주가 체결 일관성), CLAUDE.md 핵심원칙 #7
- **문제**: 예수금 부족 시 강제 부분 매도가 `price_provider`의 raw price로 `portfolio.sell_symbol_fifo`를 직접 호출하여 ExecutionModel을 우회. 슬리피지·호가 단위·세금·수수료가 모두 0으로 처리되며, sell_amount = `price * quantity`로 cash_events 기록. **일반 매도 경로(엔진)와 결과 비일관 → 강제 매도가 백테스트 수익을 비현실적으로 좋게 만든다.**
- **정책 인용**: 13.6.3 "매도 체결 시 해당 거래일에 해당하는 세율을 검색하여 적용"; 13.5 "슬리피지를 적용한 후 호가 단위로 반올림한 값이 최종 체결가".
- **권고**: CashManager가 ExecutionModel을 주입받아 `apply_slippage_and_tick + calculate_sell_proceeds`를 거친 net amount로 매도.

### C3. user_id scope 누락이 `/duplicate`까지 확장

- **권고**: 4개 엔드포인트 모두 `user_id` 의존성을 받고, service 레이어에서 `Strategy.user_id == user_id` 조건 추가; duplicate는 `src.user_id == 호출자 user_id`를 401/403으로 검증.

### C4. strategy_json validator 부재 — 잘못된 JSON이 통과되어 백테스트 시점 KeyError

- **위치**: `backend/app/schemas/strategy.py:14-29` + `routes_strategies.py:33-46`
- **위반 절**: 02번 (전체 schema), 03번 4절, 10번 7.1절 (`INVALID_STRATEGY_JSON` / `EXIT_POSITION_IN_EXIT_SIGNAL` / `UNKNOWN_CONDITION_TYPE`)
- **문제**: `StrategyCreate.strategy_json`이 `dict[str, Any]`로 무검증 통과. ConditionRegistry 미등록 type, exit_signal에 들어간 `take_profit` (requires_position=True), 잘못된 logic, GROUP 표현, position_sizing 누락 등이 전혀 검증되지 않은 채 DB에 저장되고 백테스트 시점에 KeyError로 폭발한다.
- **정책 인용**: 02번 2절 — "실행 가능한 type은 ConditionRegistry에 등록된 것만 허용한다"; 10번 7.1 — `INVALID_STRATEGY_JSON`/`EXIT_POSITION_IN_EXIT_SIGNAL`/`UNKNOWN_CONDITION_TYPE` 에러 코드 카탈로그 존재.
- **권고**: `schemas/strategy.py`에 StrategyJsonValidator 추가 — (a) registry 등록 type만 허용, (b) requires_position에 따른 섹션 라우팅 검증, (c) AND/OR/GROUP 형태 검증, (d) 4xx + 표준 에러 코드 변환.

### C5. peak_price를 adj_close로 즉시 갱신 — trailing_stop 등록 즉시 회귀

- **위치**: `backend/app/portfolio/portfolio.py:245-252` + `backend/app/backtest/engine.py:86`
- **위반 절**: 13.3.5, 13.15 look-ahead 체크리스트 4번째
- **문제**: `update_market_price(symbol, adj_close)`가 매일 호출되며 `peak_price = max(peak_price, adj_close)`로 갱신. 13.3.5는 "peak_price = max(peak_price, **당일 high**)"이며 "**다음날부터 적용**"이라고 명시. 즉 (a) `adj_high`가 아닌 `adj_close`를 쓰고 (b) 갱신이 같은 봉에 즉시 반영된다. 외부 리뷰 4.5는 trailing_stop 미구현이라 잠재적이라 평가했지만, **`peak_price` 필드 자체가 잘못된 값으로 누적 → trailing_stop 등록 순간 회귀 보장**.
- **정책 인용**: 13.3.5 "peak_price = max(peak_price, 당일 high) … 다음날부터 적용 … look-ahead bias 방지를 위해 peak_price 갱신은 전일까지의 high만 사용".
- **권고**: peak_price 갱신을 `adj_high` 기반으로 변경 + exit_position 평가 시점에는 **전일까지의** peak_price 사용 (또는 평가 후에 갱신).

## 3. 🟠 High (수정 권장 — 모듈 경계·look-ahead 잠재·스키마 검증 부재)

### H1. TradeExecution.gross_amount/net_amount 의미 어긋남

- **위치**: `backend/app/services/backtest_service.py:316-333`
- **위반 절**: 13.5/13.6/13.7, 02번 11절 (execution.tax_rate 시계열 영속화)
- **문제**: `gross_amount = ex["price"] * ex["quantity"]`로 슬리피지·호가 반올림 후 가격이 들어가 "원가" 추적 불가. `net_amount = gross`(BUY는 cost, SELL은 proceeds)이며 fee=0/tax=0 분해로 영구 누락. **외부 4.7 재확인이지만 gross까지 의미 어긋나 추후 fee/tax 도입 시 수치가 안 맞을 위험 — 회귀 케이스 추가 필요**.
- **권고**: `ExecutionResult` dataclass(gross/fee/tax/net)를 ExecutionModel이 직접 반환 → portfolio.trade_logs로 그대로 흘려 영속화.

### H2. chart-data API의 synthetic 재생성 → marker mismatch 위험

- **위치**: `backend/app/api/routes_backtests.py:139-200`
- **위반 절**: 14번 6절, CLAUDE.md 원칙 #9 (재현성)
- **문제**: 매 호출마다 `synthetic_seed`로 candles를 **재생성**. seed/n이 동일해도 BacktestEngine 실행 시점 df와 chart-data 호출 시점 df 사이 임의 차이(라이브러리 버전, numpy seed semantic 변경)가 생기면 marker가 candle과 어긋난다. **결과 차트가 영속화된 시세가 아니라 재계산 → 재현성 원칙 위반**.
- **권고**: 차트용 일봉을 별도 테이블 또는 daily_prices 테이블 조회로 이전 (외부 4.8 후속).

### H3. 백테스트 취소 신호 전파 누락

- **위치**: `backend/app/api/routes_backtests.py:303-315`

### H4. volume_ratio 기본값이 adj_volume — 거래대금 필터 호환 없음

- **문제**: `volume_field` 기본이 `adj_volume`이고 거래대금 평균 명시 없음. 13.7.3은 "거래대금 필터: 원 거래대금 사용"이며 02번 6절은 거래대금 필터 `price_field=close` 명시. **향후 `avg_trading_value` 추가 시 본 모듈을 모방하면 수정 거래량으로 거래대금을 계산하는 look-ahead-like 왜곡 발생**.
