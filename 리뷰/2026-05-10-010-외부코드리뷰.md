## 1. 총평

현재 코드는 "레고형 전략 빌더 + 단일 종목 합성 데이터 백테스트 데모" 수준으로는 상당 부분 동작한다. 그러나 상세설계서가 요구하는 MVP의 핵심인 실시장 데이터 기반 복수 종목 백테스트, 유니버스/생존편향 처리, 정확성 정책 전체 적용, 백테스트 결과의 재현 가능한 영속화, API 표준화까지 완료되었다고 보기 어렵다.

작업로그/README.md에는 "MVP 7개 Phase 모두 완료", "백엔드 272/272 통과"라고 적혀 있으나, 현재 워크스페이스 기준으로는 이 판단을 신뢰하면 안 된다. 백엔드 가상환경은 깨져 있어 테스트 실행 자체가 실패했고, 실제 코드에도 Phase 14 데이터 파이프라인 미구현 및 dev 합성 데이터 사용이 명시되어 있다.

냉정한 판정:

```text
전략 빌더 UI: 부분 구현
전략 JSON 스키마: 부분 구현, 핵심 섹션 다수 누락
조건 Registry/StrategyEngine: 구조는 양호, 조건 범위는 부족
백테스트 엔진: 단일 종목 데모 수준, 설계 MVP와 큰 차이
Portfolio/CashManager: 기본 구조는 있으나 비용/정확성/통합 미흡
시장 데이터/유니버스/데이터 파이프라인: 사실상 미구현
DB: 일부 핵심 테이블만 구현, 시장 데이터 계층 미구현
결과 UI/차트/CSV: 기본 표시/다운로드만 구현, 설계 기능 다수 누락
API: 일부 CRUD/조회만 구현, 설계 표준과 엔드포인트 누락 많음
테스트: 프론트 통과, 백엔드는 현재 환경에서 실행 불가
```

### 5.2 도메인 validator 부재

### 5.3 비용 분해 손실

ExecutionModel은 수수료/세금을 계산하지만, 영속화 시 fee/tax를 0으로 저장한다. 이는 CSV, 세금 분석, 재현성 검증을 깨뜨린다.

수정 지시:

```text
ExecutionResult dataclass(price, gross, fee, tax, net)를 도입한다.
Portfolio trade_logs에도 fee/tax를 포함한다.
```

### 5.4 체결일 정합성 문제

next_open 체결을 구현하면서 거래 로그 날짜는 신호일 today로 기록한다. 결과 차트, holding_days, CSV, 세금 적용 날짜가 모두 왜곡될 수 있다.

수정 지시:

```text
df에 next_date를 추가하거나 idx+1 row를 직접 참조한다.
BUY/SELL execution_date는 실제 체결일로 저장한다.
signal_date는 notes 또는 별도 필드로 남긴다.
```

### 5.5 API 비동기/취소는 형식만 있음

BackgroundTasks는 실행 중 진행률을 갱신하지 않고, cancel도 엔진이 확인하지 않는다.

수정 지시:

```text
run.progress_pct를 날짜 루프마다 갱신한다.
BacktestEngine에 should_cancel 콜백을 주입한다.
cancelled 상태 감지 시 partial result를 폐기하거나 명시 정책대로 저장하지 않는다.
```

## 8. 최종 판정

현재 프로젝트는 "상세설계서 기준 MVP 완료"가 아니다.

현재 상태를 정확히 표현하면 다음이 맞다.

```text
전략 생성 UI와 단일 종목 합성 데이터 백테스트 데모는 동작한다.

```

다음 코딩은 기능 추가보다 먼저 신뢰성 기반을 복구해야 한다. 특히 백엔드 테스트 환경 복구와 실데이터 인터페이스 도입 없이는 이 프로젝트의 백테스트 결과를 사용자에게 보여주면 안 된다.
